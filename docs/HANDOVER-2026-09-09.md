## 一、做完的事（一句话）

把 yupi 风格在线判题单体后端，按已批准设计（`docs/superpowers/specs/2026-09-08-onlinejudge-microservice-refactor-design.md`）改造成 **Spring Cloud Alibaba 微服务**：8 个 Maven 模块、四业务服务 + 网关统一鉴权、共享 model/common/service-client；微信/公众号/COS 业务去除（FileController 代码未迁移）；判题闭环经 RabbitMQ 解耦。**四个服务迁移与整体/远程沙箱联测全部完成并通过。**

## 二、架构与模块（现状即最终）

```
前端 ──► onlinejudge-gateway :8888  （统一鉴权：验签+Redis会话+每请求快照+剥/注入 X-User-*+ban 硬拒+续签；路由不剥前缀）
            ├─ onlinejudge-user-service     :8101  /api/user/**  登录签发/会话/登出；/api/inner/user/{id}/snapshot|vo|list/vo
            ├─ onlinejudge-question-service :8102  /api/question/** admin增删改查+公开读；/api/inner/question/{id}
            ├─ onlinejudge-submit-service   :8103  /api/question_submit/** 提交→DB(WAITING)→Rabbit code-queue；校验题/拼user走Feign
            └─ onlinejudge-judge-service    (无HTTP) 消费 code-queue→判题→同库回写 question/question_submit
共享库：onlinejudge-model(纯数据+model.result错误体+model.auth.JwtUtils) / onlinejudge-common(身份头鉴权件+异常+常量) / onlinejudge-service-client(Feign: UserServiceClient/QuestionServiceClient)
中间件：Nacos(8848) 注册发现 | MySQL onlinejudge 单库 | Redis db2 | RabbitMQ code-exchange/code-queue | 判题沙箱 Docker(prod) / 本地example(dev)
```

- 技术基线：Java8 + Spring Boot 2.6.13 + Spring Cloud 2021.0.5 + Spring Cloud Alibaba 2021.0.5.0（聚合 pom 统一版本；无 SB4/Java17 残留）。`--release 8` 编译。
- **网关不依赖 common**（WebFlux 与 servlet 冲突），只依赖 model + spring-data-redis-reactive。错误体 `model.result.BaseResponse/ErrorCode/ResultUtils` 全网统一（HTTP 200 + code：40100 未登录 / 40101 无权限/封禁 / 40102 被踢 / 40400 不存在 / 50000 系统）。
- **鉴权模型**：网关唯一入口；`X-User-Id/Role/Name/Avatar/Device-Type` 由网关按每请求实时快照注入（用户被封≤当下生效）；服务用 common `IdentityHeaderFilter`+`AuthRoleAspect`+`@AuthCheck` 只信身份头；**服务端不做 token 解析、Feign 内网调用不带用户头**（安全边界：服务端口须仅内网可达，否则可伪造 X-User-*）。
- 跨服务拼 VO：question/submit 拼创建人/提交人 `user` → `UserServiceClient`（Feign 批量，服务端脱敏）；submit 校验题目 → `QuestionServiceClient`。判题→judge 走 MQ；judge 回写计数保留同库直连（"先单库"决策）。

## 四、如何运行（本地联调）

前置：MySQL(`onlinejudge` 库，root/123456789，表来自单体 `sql/create_table.sql`)、Redis(6379, db2)、Nacos(8848)、RabbitMQ(5672, guest/guest)。判题 dev=本地 example 沙箱；**连接真实远程 Docker 沙箱**见下。

```bash
cd D:/Java_project/onlineJudge-cloud/onlineJudge
mvn -DskipTests install                     # 全量编译（JDK17 下 --release 8）
# 依次（各开终端或后台）：
java -jar onlinejudge-user-service/target/onlinejudge-user-service-0.0.1-SNAPSHOT.jar
java -jar onlinejudge-question-service/target/onlinejudge-question-service-0.0.1-SNAPSHOT.jar
java -jar onlinejudge-submit-service/target/onlinejudge-submit-service-0.0.1-SNAPSHOT.jar
java -jar onlinejudge-judge-service/target/onlinejudge-judge-service-0.0.1-SNAPSHOT.jar   # 消费者；dev 用 example
java -jar onlinejudge-gateway/target/onlinejudge-gateway-0.0.1-SNAPSHOT.jar
```
- 走通路径：`POST :8888/api/user/register` → `login`(拿 token) → 带 `Authorization: Bearer <at>` 访问各 `/api/...`；admin 需把该用户 `userRole` 置 `admin`（DB UPDATE，本地演示用）→ 建题 → 提交 → 轮询 `get/vo` 到 status 2/3。
- **远程沙箱（真实判题）**：judge 用 JDK（非 JRE）并加参数：
  `java -jar onlinejudge-judge-service/target/...jar --codesandbox.type=docker --codesandbox.url=http://192.168.38.129:8201/docker/ --codesandbox.auth-secret=online_judge_project_secret_key`
  远程沙箱 `192.168.38.129:8201` 当前可达；DockerCodeSandBox POST `{url}` + header `auth: md5(auth-secret)` + ExecuteMessage JSON（10s 超时）。
- 服务 yml 里的账号/密码为本地 dev 实配；生产需覆盖。
